# Lane A — Is There an Open-Source Dealer Management System to Stand On?

**Summary — what I found and what I didn't:**
No major DMS (CDK Drive, ADP Dealer Services lineage, Reynolds ERA) has ever been open-sourced, published an open schema, or offered a community edition — all programmatic access is gated behind partner/certification programs ([Fortellis](https://fortellis.io), [Reynolds Certified Interface](https://www.reyrey.com/partners/reynolds-certified-interface)). A prior "OpenDMS" effort was confirmed to not actually exist as code ([opendms.org](https://opendms.org/), [David P. Nelson's blog](https://davidpnelson.wordpress.com/open-source-dealership-management-system-open-dms/)). Several genuinely open, actively maintained general-purpose ERPs exist (Odoo Community, ERPNext, iDempiere, OFBiz) with generic fleet/repair/inventory modules, but none has dealership-specific F&I, deal-jacket, or repair-order/VIN logic, and none has ever been extended to heavy-truck scale. No open-source garage/workshop system exists above hobby scale, and no open-source heavy-truck/Class-8 DMS or fleet-maintenance system exists at all — the closest thing to an open truck-maintenance data standard, VMRS, is in fact a paid, copyrighted license product of ATA's Technology & Maintenance Council, not open source. The realistic conclusion, evidenced below, is that no open-source DMS is a viable foundation to build on directly.

## 1. Has CDK Drive, ADP, or Reynolds ERA Ever Been Open-Sourced?

**No — definitively, on all three counts.**

- **CDK Global** exposes DMS functionality only through **Fortellis**, a proprietary developer marketplace requiring a paid solution registration, client ID/secret, and rate-limited API access (100 calls/60 sec) — this is API-gating, not open source, no license grant, no published schema for public use. Source: [Fortellis](https://fortellis.io), [Microsoft Learn — CDK Drive Customer connector](https://learn.microsoft.com/en-us/connectors/cdkdrivecustomer/).
- CDK Global's own GitHub organization (`github.com/CDKGlobal`) contains 28 public repositories, but every one is a fork of unrelated internal DevOps tooling (Puppet modules, Kafka mirrors, a Docker fork) — nothing touches the DMS product itself. Source: [github.com/orgs/CDKGlobal/repositories](https://github.com/orgs/CDKGlobal/repositories).
- **Reynolds and Reynolds** has no public API or developer portal at all. All third-party programmatic access runs through the **Reynolds Certified Interface (RCI)**, a certification-gated, contract/NDA-based partner program with no public API reference or OpenAPI spec. Source: [Reynolds and Reynolds RCI program](https://www.reyrey.com/partners/reynolds-certified-interface), [APIs.io Reynolds provider listing](https://apis.io/providers/reynolds-reynolds/) (which itself records no public spec).
- **ADP Dealer Services** is the historical ancestor of CDK Drive (spun off as CDK Global in 2014); no evidence of any open edition or open schema was found for this lineage either — it inherits the same closed posture as its CDK Drive successor.
- A community effort branded **"OpenDMS"** (opendms.org, claiming to build an open DMS on Odoo) was checked directly: the site is aspirational marketing with no linked code repository, no maintainer name, no version history. Source: [opendms.org](https://opendms.org/). A named individual's own blog post about this same effort states plainly: *"Full disclosure – OpenDMS doesn't exist."* Source: [David P. Nelson's blog](https://davidpnelson.wordpress.com/open-source-dealership-management-system-open-dms/).
- The one genuine open **standard** (not software) touching this space is **STAR (Standards for Technology in Automotive Retail)**, which publishes 200+ XML Business Object Documents covering customer, parts, sales, service/repair-order, vehicle inventory, F&I/credit, and financial-statement data, built on W3C XML Schema and UN/CEFACT CCTS/OAGIS methodology. In January 2026 STAR released a new JSON-based "Automotive Retail Domain Model" explicitly framed around supporting dealership "digital twins." Sources: [STAR XML BODs](https://www.starstandard.org/index.php/star-xml-bods/), [STAR Domain Model announcement](https://www.starstandard.org/index.php/2026/01/27/star-unveils-industry-defining-retail-automotive-domain-model-to-advance-data-interoperability-and-ai-transformation-across-the-entire-ecosystem/). This is **not free or open-access for participation**, however: full Technology Provider membership dues run **$10,000–$50,000/year** by revenue tier, and OEM membership is a flat **$20,000/year**; only paying members may author or update the domain model, though the published documentation itself is viewable by non-members. Sources: [STAR 2024 Technology Provider Membership schedule (PDF)](https://www.starstandard.org/wp-content/uploads/2024/03/2024-STAR-Technology-Providers.pdf), [STAR FAQs](https://www.starstandard.org/index.php/faqs/). STAR's stated scope nominally extends to "Medium & Heavy-duty Trucks," but no truck-specific schema depth beyond what's shared with light-vehicle retail was found in the fetched BOD catalogue — this is noted as an inference, not confirmed absence.

**Bottom line for item 1: no open-sourcing, no open schema release, no community edition, and no free client library exists for CDK Drive, ADP, or Reynolds ERA.** The only open artifact adjacent to this space (STAR) is a paid-membership standard, not source code.

**Compiere lineage, for context:** Jorg Janke created Compiere around 1999–2000 (with early funding tied to Goodyear), releasing it under GPL as one of the first viable open-source ERPs. Venture financing in 2006 pushed Compiere Inc. toward a commercial "Enterprise" license, triggering a community fork into **ADempiere** (Sept 2006, GPL v2, community-governed and never re-proprietized). A further 2011–2012 modularization using OSGi produced **iDempiere**, the most actively developed branch today. **Metasfresh** is a separate, later German fork of the same lineage that now shows no confirmed release newer than mid-2023. None of these forks has ever added automotive- or dealership-specific modules.

## 4. Heavy Truck / Class 8 Open Source — Dealership or Fleet Maintenance

**No dedicated heavy-truck/Class 8 dealership open-source system was found anywhere — GitHub, GitLab, or the open web.**

Generic small-scale fleet-maintenance open-source projects exist, but none is truck- or Class-8-specific, and none reaches production scale:

- [fleetms (jmnda-dev)](https://github.com/jmnda-dev/fleetms) — AGPL-3.0, explicitly labeled "work in progress."
- [OpenFleet (warrengalyen)](https://github.laiyagushi.com/warrengalyen/OpenFleet) — .NET 8 + React, MIT license, single-maintainer demo-quality project.
- [Fleetco](https://sourceforge.net/projects/fleetco/) — PHP/MySQL, GPLv3, SourceForge-hosted, originally aimed at trucking companies but appears low-activity/legacy based on its hosting platform and lack of recent updates.
- A vendor/services page for "ZentroFleet" claims an open-source small-fleet tool but presents as marketing content rather than a verifiable primary-source repository — not independently confirmed and not counted as a real finding here.
- One secondary source (a "reality check" blog post on vehicleprohub.com) claimed a Daimler Truck "FleetBoard Open" project, describing it in its own words as **"source-available under a restrictive license... a marketing exercise, not a solution,"** limited to Mercedes-Benz/Freightliner. The same article also referenced "OpenVehicle" and a second "OpenFleet" with suspiciously precise, uncorroborated technical claims (exact star counts, exact OEM service intervals) that could not be verified elsewhere. This source is flagged low-confidence and its specific technical claims are not treated as fact here — noted per the rule that absence of verification must be recorded, not smoothed over.

**On VMRS specifically** (Vehicle Maintenance Reporting Standards) — the actual data-coding backbone of North American heavy-truck maintenance, and the closest thing to an "open" heavy-truck data standard: it is **not open**. VMRS is developed and exclusively licensed by the American Trucking Associations' Technology & Maintenance Council (TMC). There are four paid license tiers (Electronic Catalog, Complete–Corporate, Complete–Developer, Complete–Distribution), priced by company revenue or user count, ranging from roughly $350/year (smallest Electronic Catalog tier) up to $50,000+/year (largest Distribution tier); a printed/electronic handbook itself costs $195–$260. Software vendors (e.g. Karmak) must separately license VMRS data to embed it in their products — Karmak's own March 2025 announcement confirms it had to license VMRS data from TMC for its Fusion platform, which it would not need to do if VMRS were open. Sources: [TMC "It's Time for a Repair!" VMRS pricing flyer (PDF)](https://tmc.trucking.org/sites/default/files/VMRS_flyer_2021_web.pdf), [TMC VMRS Overview](https://tmc.trucking.org/VMRS-Overview), [Transport Topics — TMC updates VMRS licenses](https://www.ttnews.com/articles/tmc-updates-vmrs-licenses-moves-annual-subscription-0), [Karmak licenses TMC's VMRS](https://www.truckpartsandservice.com/technology/business-operations/article/15739616/karmak-licenses-tmcs-vehicle-maintenance-standards).

**Finding: no open implementation of fleet-maintenance data specifically for heavy truck/Class 8 exists as a real, maintained, primary-sourced project, and the underlying coding standard (VMRS) is itself a paid, copyrighted licensing product — not open source, not a free standard.** This is an absence-of-evidence finding.

## 5. Commercial Heavy-Truck DMS Landscape (Descriptive Only)

Documented purely to establish what a full truck-dealership system contains — not evaluated as a purchase option, per the task rules.

- **Karmak** — employee-owned, 40+ years in commercial-vehicle software. Products: **Fusion** (core system for large multi-location dealer groups), **Blaze** (cloud SaaS DMS, gained via the DSI Solutions acquisition effective 30 Sept 2025), **Truckmore** (DMS-agnostic customer engagement/mobile app, acquired 2022). Covers parts, service, accounting, lease/rental, and vehicle sales; integrates with DTNA, **PACCAR**, International, and Mack/Volvo. Karmak states it holds over 50% of PACCAR's DMS market share. Sources: [karmak.com](https://www.karmak.com/), [karmak.com/products](https://www.karmak.com/products), [Karmak acquires DSI Solutions — PR Newswire](https://www.prnewswire.com/news-releases/karmak-acquires-dsi-solutions-cementing-industry-leadership-and-expanding-dealer-management-offerings-302582870.html).
- **Procede Software** — **Excede DMS**, in market since 2001, built on Microsoft SQL Server, serves truck/trailer/bus/aftermarket dealerships across the US, Canada, and Australia. Covers accounting, parts, service, lease/rental, and vehicle sales; named Hino Trucks' preferred DMS provider in 2023. Sources: [procedesoftware.com/excede](https://www.procedesoftware.com/excede/), [procedesoftware.com/truck](https://www.procedesoftware.com/truck/).
- **Trimble TMT (TMT Fleet Maintenance)** — single-tenant, web-based fleet-maintenance system covering repair orders, preventive maintenance, parts inventory, accounting, and mobile integration. Sources: [Trimble TMT developer docs](https://developer.trimble.com/docs/tmt/), [Trimble Transportation — fleet maintenance](https://transportation.trimble.com/en/solutions/fleet-maintenance).
- **Dossier Fleet Maintenance Software** — used by 4,000+ private, for-hire, and public fleets per vendor claims; covers PM scheduling, repair orders/histories, fuel/MPG tracking, cost-per-mile, parts inventory with auto-reordering, warranty management, tire management, and VMRS coding. Source: [SourceForge Dossier product listing](https://sourceforge.net/software/product/TMT-Fleet-Maintenance/) (an aggregator page describing the vendor's own claims).
- **Decisiv** — Service Relationship Management (SRM) platform; integrates with Trimble TMT via a "TMT ServiceConnect" module; operates a network of roughly 4,500 service-center/OEM partners for cross-shop visibility into equipment status, scheduling, and service history. Sources: [Decisiv/TMT ServiceConnect overview (PDF)](https://www.decisiv.com/wp-content/uploads/2019/03/Final-TMT-ServiceConnect-TMC-Overview-20190315_1-12.pdf), [CCJ Digital — Decisiv and Trimble close the loop](https://www.ccjdigital.com/business/article/14938124/decisiv-and-trimble-close-the-communication-loop).

Taken together, these confirm the full functional shape of a heavy-truck DMS/fleet-maintenance stack: **accounting, parts inventory with reordering, service/repair orders, PM scheduling, warranty/tire/VMRS-coded records, lease/rental, vehicle sales, OEM (including PACCAR) integration, and cross-shop service-network connectivity.**

## 6. Assessment: Is "Start From an Open-Source DMS" a Real Option?

The evidence above supports a clear conclusion: **no, not as a wholesale foundation.** The reasoning, by category:

- **No open-source project of any kind covers dealership-specific transactional logic** — deal jacket, F&I, VIN-decoded repair orders, or dealership-grade parts catalogues — at any scale above coursework demos. Every general-purpose ERP surveyed (OFBiz, Odoo, ERPNext, Tryton, Dolibarr, Metasfresh, the iDempiere/ADempiere/Compiere lineage) is a capable, license-clean back-office engine (accounting, generic inventory, generic CRM) but stops well short of dealership semantics. Odoo Community/OCA is the strongest of these on functional breadth (a real Fleet module plus a Maintenance-Repair Order bridge), and it is also the most actively maintained (commits as recent as 15 Jul 2026), but its fleet/repair scope is built for light-vehicle fleet tracking, not dealership deal-flow or truck-service operations.
- **No open-source project — anywhere — addresses heavy truck / Class 8 at all.** This is the more decisive finding for this specific group, since the core business here is heavy truck, not car retail. Not one candidate, of any maturity level, has ever added Class 8-specific logic, VMRS-coded repair-order structures, or PACCAR/DTNA-style OEM integration.
- **The one candidate literally named "the first Open Source Web Dealership Management System" (Automotis) is a dead, single-star repository last touched in 2011** — a direct illustration of why "search until you find a name" is the wrong test; liveness, not existence, is what matters, and by that test this category is empty.
- **The nearest thing to an open data standard for this domain, STAR, is not open** — it requires $10,000–$50,000/year membership to participate in authoring, though its published BOD catalogue and new 2026 Domain Model are informative as a *reference schema* to study, even without a license to build on it directly. Its heavy-truck coverage claim is unverified beyond the stated scope note.
- **VMRS, the actual language of heavy-truck maintenance data, is a paid, copyrighted licensing product of TMC/ATA — not open, not free, not a standard anyone can adopt without a subscription.** Any dealer-owned twin that wants to speak VMRS to be compatible with the commercial heavy-truck DMS ecosystem (Karmak, Procede, Trimble TMT, Decisiv all use VMRS) will need to license it, the same as those commercial vendors do — there is no open substitute.

**On the evidence, the realistic path is a purpose-built data model — informed by STAR's and VMRS's published schema shapes as design references even where their code/data itself isn't free to use — built on genuinely open general-purpose components underneath it** (a warehouse/orchestration/BI layer, and optionally an open-core ERP such as Odoo Community or iDempiere for generic back-office functions like accounting or basic inventory), rather than adopting or forking any existing open-source project as a DMS skeleton. No surveyed candidate reduces the amount of dealership-specific or truck-specific modeling work that has to be done from scratch; at best, the strongest general ERPs (Odoo, iDempiere) save effort only on the non-dealership-specific back-office plumbing.
