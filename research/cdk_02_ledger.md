# CDK Drive — Lane 2: Financial Ledger (Chart of Accounts, Schedules, Journal Mechanics, Close, Floor Plan, Warranty)

Client: EVEglyphDesign digital twin for Peterbilt Atlantic. Public sources only. All claims tagged `DOCUMENTED` or `INFERRED (dealer-accounting norm)`.

## 1. Dealership chart of accounts — OEM-mandated structure

`DOCUMENTED`. Every major OEM (GM, Ford, and by the same market convention PACCAR/Peterbilt/Kenworth) requires franchised dealers to submit a monthly financial statement in a **factory-defined format**, which forces the dealer's chart of accounts to map onto factory-standard account numbers regardless of which DMS the dealer runs. GM's is formalized as the **GM Dealer Standard Accounting Manual and Classification of Accounts** ([gm.acctmanual.com](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf)). Ford runs the same concept as the **Ford Online Accounting Manual / Chart of Accounts** ([Ford dealerconnection](https://www.fmcdealerfbmi.dealerconnection.com/AccountingManual/en/coa-coacmplt-en-htm/)). DMS vendors sell "Formatted Financial Statement" modules that translate a dealer's live GL into the OEM layout — e.g. SDS/Series describes this directly: *"Certain manufacturers require that your financial information be given them in a specific format... Assign all your General Ledger accounts to standard account numbers which correspond to the account numbers on the manufacturer's forms"* ([SDS Documentation X159-1](https://sdswebservices-soldoc.serti.com/sds-documentation/55b/en/x159/x159-1.pdf)).

PACCAR's own SEC disclosures confirm PACCAR Financial Services runs **dealer wholesale financing** (floor plan) and monitors dealers' financial position as part of that credit relationship ([PACCAR 10-K, SEC](https://www.sec.gov/Archives/edgar/data/731288/000095017024017921/pcar-20231231.htm)), which is the same mechanism (factory reporting + floor plan credit control) documented for GM/Ford. `INFERRED (dealer-accounting norm)`: PACCAR/Peterbilt/Kenworth dealers are contractually required to submit a **Dealer Composite/factory-format financial statement** analogous to GM's and Ford's; no public PACCAR-specific chart-of-accounts manual (equivalent to GM's or Ford's) was locatable — this is an open item.

### Account numbering conventions (documented via GM manual, structurally identical pattern used industry-wide)

| Convention | Rule | Example |
|---|---|---|
| Base account number | 3-digit number identifies the natural account (asset/liability/revenue/expense classification) | `231` = New Cars inventory |
| Department suffix | Expense (and many revenue) accounts append a 2-digit department code after a hyphen | `013-01` = Delivery Expense, New Vehicle Dept |
| Department code table | 01 New Vehicles, 02 Used Vehicles, 03 Lease & Rental, 04 F&I, 05 Mechanical/Service, 06 Body Shop, 07 Parts & Accessories, 09 General & Administrative | — |
| Sub-account letter suffix | A letter suffix on an account further splits it for analysis/audit, independent of department | `446A` Used Cars Retail–Certified vs `446B` Used Cars Retail–Other |
| Numeric ranges by statement section | 200s = assets, 300s = liabilities/equity, 400s = sales (revenue), 600s = cost of sales, 700s = lease/rental cost detail, 800s/900s = other income/expense and F&I | `220` AR-Customers; `400-418` New Cars Retail Sales; `600-618` New Cars Retail COGS |

(Source for full table and rules: [GM Dealer Standard Accounting Manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf).)

Illustrative accounts relevant to this twin: `205` Contracts in Transit, `220` AR-Customers, `231` New Cars, `240` Used Cars, `247` Work In Process–Labor, `261` Factory Receivables, `263` Warranty Claims, `300` AP-Trade Creditors, `310` Notes Payable–New Vehicles/Demonstrators (floor plan), `320` Interest Payable, `076-01/02` Interest Floorplan by department ([GM manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf); [GM Interest Floorplan account detail](http://gm.acctmanual.com/Expenses/076_Interest_Floorplan.htm)).

## 2. Accounting schedules — the DMS subledger mechanism

`DOCUMENTED`. A **schedule** in dealership-DMS accounting is a subledger report of open-item detail behind a single GL balance, distinct from the GL account itself, which only carries a summarized period-end total: *"A schedule is simply a complicated report of accounting detail"* and clears "when the balance for the RO# (control) is zero after the month's end" ([Digital Dealer, "Your DMS and Schedules"](https://digitaldealer.com/news/your-dms-and-schedules/65829/)). A schedule is said to be **"controlled"** by a designated key field — RO number, stock number, customer ID, VIN-last-8, reference/document number — and the DMS must know, per account, whether to require that control number at posting time or derive it automatically ([Digital Dealer](https://digitaldealer.com/news/your-dms-and-schedules/65829/)). This differs from a generic ERP subledger in that a standard ERP typically has only two controlled subledgers (AR and AP); a DMS extends the same "control account" pattern to **every schedule-based GL account** — floor plan payable, factory receivables, warranty claims, contracts-in-transit, F&I chargebacks, service/parts work-in-process — because nearly every dealership transaction traces back to a deal, RO, or parts ticket ([Digital Dealer](https://digitaldealer.com/news/your-dms-and-schedules/65829/)).

The same "controlled account" concept is described independent of CDK by other DMS vendors: DealerStar's feature sheet notes GL accounts can be "controlled individually by Cust#, Stock#, last8, Reference, VIN" ([DealerStar DMS Feature Worksheet](http://www.dealerstar.com/images/DMSFeatureWorksheet.pdf)); Autosoft's Dealership Accounting Schedules and Documents manual describes "Detail Forward Schedules," "Balance Forward Schedules," "Schedule Purification Lists," and "Schedule FasTrial" as concrete UI screens built on this same control-account model ([Autosoft Schedules manual](https://download.autosoft-asi.com/instructions/A/Schedules.pdf)); Autosoft's setup manual literally has a field labeled **"Schedule Controlled With"** where the control key (document number, stock number, VIN, customer number) is defined per GL account ([Autosoft Accounting manual](https://download.autosoft-asi.com/instructions/A/Accounting.pdf)). Dominion DMS's help docs likewise show a GL account setup screen with "Account Prefix/Master/Sub" and "Reporting Accounts" mapped per financial-statement line ([Dominion DMS help](https://help.dominiondms.com/en/knowledge/create-a-new-sales-general-ledger-account)). Industry commentary (2026) reiterates the same principle at the category level: *"Contracts in transit, vehicle inventory, floorplan payable, we-owes, factory receivables, finance reserves. Every one is a sub-ledger of individual items that must clear, and month-end means reconciling all of them to the general ledger"* ([Voltra, Dealership Accounting Software 2026](https://voltra.ai/blog/dealership-accounting-software/)).

### Documented example — why the schedule/GL split matters

Ford's own chart uses **Account 1140 "Warranty Claims Receivable"** as the GL control account; the underlying schedule detail is the open list of individual claims by RO/claim number, which a dealer can implement either as an AR-module customer sub-ledger ("Ford Warranty Receivable" customer, cleared by claim/RO number under an open-item method) or as a dedicated schedule against account 1140 ([Digital Dealer, citing Ford's chart](https://digitaldealer.com/news/your-dms-and-schedules/65829/)). GM's manual shows the identical structural pairing under different numbering: **Account 263 "Warranty Claims"** is debited for claims filed and credited for factory payments/rejections, with an explicit note that differences between "the month-end schedule and the account balance" are themselves adjusting entries — direct textual proof that the schedule and the GL account are two separate, reconciled artifacts ([GM Dealer Standard Accounting Manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf)).

| Schedule type | GL control account (GM numbering) | Control key | Behavior |
|---|---|---|---|
| Warranty claims receivable | 263 Warranty Claims | RO#/claim# | Aged schedule (30/60/90/120+), detail-forward, clears at zero balance |
| New vehicle floor plan | 231 New Cars (asset) vs 310 Notes Payable–New Vehicles (liability) | Stock#/VIN-last-8 | Viewed side-by-side vs inventory; flags units floored after sale |
| Factory receivables (holdback, incentives, SFE/Pinnacle, MSP) | 261 Factory Receivables | claim/program reference | Reconciled monthly to OEM statement |
| Contracts in transit | 205 Contracts in Transit | deal/contract # | Clears when funding received from lender |
| Service/parts WIP | 247 Work In Process–Labor / parts WIP accounts | RO# | Clears when RO closes/invoices |

(All rows sourced to [GM Dealer Standard Accounting Manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf) and [Digital Dealer](https://digitaldealer.com/news/your-dms-and-schedules/65829/).) `INFERRED (dealer-accounting norm)`: CDK Drive's own internal schedule numbers (equivalent to Autosoft's GLSKEDS export or Ford's 1140) were not located in any public CDK/Fortellis document — flagged below.

## 3. Journal entry mechanics in CDK Drive

`DOCUMENTED` — journal types (from GM manual, used as the accounting-flow reference since it enumerates named journals a DMS posts into, and matches CDK training materials' generic terminology pattern): Standard Entries Journal, Cash Receipts Journal, Cash Disbursements Journal, Purchase Journal, Payroll Journal, New Vehicle Sales/Purchase Journal, Used Car Sales Journal, Internal Sales Journal, Service Sales (Cash/Charge) Journal, Warranty Sales Journal, Parts Sales (Cash/Charge) Journal, Dealer Exchange Journal, Statistical Data Journal, General Journal Entry ([GM Dealer Standard Accounting Manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf)). A concrete GM-manual journal entry example shows the department-suffix posting convention in practice: floor plan interest accrual debits `076-01 Interest Floorplan – New Vehicles` and `076-02 Interest Floorplan – Used Vehicles` and credits `320 Interest Payable`, posted through the **Standard Entries Journal** ([GM Interest Floorplan, Account 076](http://gm.acctmanual.com/Expenses/076_Interest_Floorplan.htm)).

`DOCUMENTED` — Autosoft's Dealership Accounting Journal Entries manual shows a directly CDK-parallel screen: journal entries specify a **Document number**, a **Journal number** (e.g. "80, General Journal" by default), a **Schedule** field to clean/adjust, and an **Adjust To** GL account — confirming that in DMS-class software, journal entry headers always carry (a) a journal type/number, (b) a posting period, and (c) an optional schedule/control reference ([Autosoft Journals manual](https://download.autosoft-asi.com/instructions/A/Journals.pdf)).

**Posting-period control / closed-period prevention:** `INFERRED (dealer-accounting norm)`. No CDK Drive screen name for period-lock was found in public materials. The general DMS/ERP pattern — documented for adjacent systems — is that once a period is closed, subledger modules are blocked from posting back into it and corrections must be entered as reversing/current-period adjustments; e.g., Microsoft Dynamics GP guidance: *"Soft close fiscal periods after period closure... If transactions are posted to prior periods after closing it can cause both the current period and previous periods to be out of balance"* ([ERP Software Blog, Dynamics GP Subledger Reconciliation](https://erpsoftwareblog.com/2018/07/dynamics-gp-subledger-reconciliation-best-practices/)). This is the same architectural principle SAP FI implements via posting-period variants (OB52) — the operator's own domain — but no CDK-specific screen/table name can be verified publicly, so it is marked `UNVERIFIED`.

## 4. Month-end close sequence and factory statement submission

`DOCUMENTED` (GM manual, generalizable pattern): each major balance-sheet schedule must be reconciled to its GL control account before close — *"Supporting month-end schedules should be prepared. These schedules should be in agreement with the general ledger accounts and compared to physical inventories"* (stated for new/used vehicle inventory accounts) ([GM Dealer Standard Accounting Manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf)). Factory receivable balances (holdback, incentives) must be reconciled specifically **to the manufacturer's own statement**: *"The month-end balance of new vehicle holdback due should be reconciled with the manufacturer's statement. Any difference should be determined and corrected"* ([GM manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf)). Used-vehicle inventory must be adjusted to appraised wholesale value through dedicated adjustment accounts (649/653) at each month end, and LIFO reserve adjustments are calculated and carried to the operating statement summary page ([GM manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf)).

A real-world close-speed benchmark for a Peterbilt-branded rooftop, on a competing DMS, is documented by Procede Software: *Peterbilt of Atlanta closes the month in three standard working days using Excede* ([Procede Software customer story](https://www.procedesoftware.com/customer-stories/how-peterbilt-of-atlanta-streamlines-accounting-and-closes-the-month-in-just-three-standard-working-days/)) — evidence that a fast, schedule-reconciliation-driven close is an industry expectation specifically in the Peterbilt dealer network, though it does not describe CDK Drive itself.

`INFERRED (dealer-accounting norm)`: The generic sequence, reconstructed from the GM manual's account-by-account reconciliation instructions plus the schedule/GL-control mechanism in Section 2, is: (1) close/cut off all subsidiary schedules (deals, ROs, parts tickets) for the period; (2) reconcile every controlled schedule to its GL account balance and post adjusting entries for variances; (3) reconcile factory receivable/holdback/incentive accounts to the OEM's own dealer statement; (4) post LIFO/inventory valuation adjustments; (5) run trial balance; (6) generate the factory-formatted financial statement and transmit/upload it to the OEM (or the OEM's designated aggregator) on the manufacturer's monthly schedule. No CDK-specific screen name for the submission step is publicly documented — `UNVERIFIED`.

## 5. Trial balance and financial statement generation — OEM format vs GAAP/ASPE

`DOCUMENTED`: DMS-class systems generate the OEM-format statement by mapping every live GL account to a **standard/reporting account number** defined by the manufacturer, independent of the dealer's own internal account numbering — *"Assign all your General Ledger accounts to standard account numbers which correspond to the account numbers on the manufacturer's forms... To produce Formatted Financial Statements with the correct format, it is essential that you execute the above steps first"* ([SDS Documentation, Formatted Financial Statement X159-1](https://sdswebservices-soldoc.serti.com/sds-documentation/55b/en/x159/x159-1.pdf)). The same source shows the DMS can print three distinct outputs from one ledger: the **Formatted (factory) Financial Statement**, the **Trial Balance**, and the **Dealer Values report** ([SDS X159-1](https://sdswebservices-soldoc.serti.com/sds-documentation/55b/en/x159/x159-1.pdf)) — i.e., one chart of accounts, multiple presentation layers. Dominion DMS's GL setup screen literally has an action button "**Reporting Accounts**" where the user enters "the appropriate Reporting Account number for each Financial Statement listed" per GL account — direct evidence of a many-to-one mapping from internal GL accounts to one or more external statement formats (OEM statement vs. internal/GAAP statement) ([Dominion DMS help](https://help.dominiondms.com/en/knowledge/create-a-new-sales-general-ledger-account)).

`INFERRED (dealer-accounting norm)`: The OEM factory statement is a management/compliance report keyed to the manufacturer's own line-item definitions (e.g., holdback, incentives netted a specific way, LIFO shown on a dedicated schedule page) and is not itself represented as a GAAP or ASPE-compliant statement; the dealer's accountant/CPA separately produces GAAP (US) or ASPE (Canada, relevant to Peterbilt Atlantic) financial statements from the same underlying GL, with different treatment of items such as LIFO (a US tax-driven method not permitted under IFRS/ASPE) and consolidation. No public CDK document was found describing a CDK Drive screen that outputs a labeled "GAAP statement" or "ASPE statement" — `UNVERIFIED`.

## 6. Vehicle inventory accounting — floor plan, curtailment, unit cost

`DOCUMENTED` — unit cost accumulation (GM Account 231, "New Cars," structurally identical for trucks): debited for (1) factory invoice amount less holdback and non-vehicle items like ad funds, (2) internal price of dealer-installed accessories/optional equipment plus install labor/materials, (3) destination/delivery/handling charges, (4) cost of units transferred in from demo/temporary service; credited for accessories/tires removed and moved to parts/tire inventory, subsequent factory price reductions, transfers to demo or other dealers, and cost of units sold/disposed ([GM Dealer Standard Accounting Manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf)). Floor plan interest is **not** capitalized into this inventory account under GM's documented treatment — it posts as a period expense (`076-01/02 Interest Floorplan`) against Interest Payable ([GM Interest Floorplan account](http://gm.acctmanual.com/Expenses/076_Interest_Floorplan.htm)), which is the standard treatment (floor plan interest is expensed, not inventoried, distinguishing it from capitalized carrying costs in other industries).

**Floor plan financing and curtailment** — `DOCUMENTED` from a bank-regulatory source describing the mechanism generally applicable to auto/truck floor plan lending: *"Floor plan advances are typically repaid as the inventory is sold, but a curtailment provision that requires periodic principal reductions by the dealer for stale inventory is normally included in the agreement... Curtailments are usually set forth in the bank-dealer loan agreement or the manufacturer-dealer agreement"* ([OCC Comptroller's Handbook, Floor Plan Lending](https://www.occ.treas.gov/publications-and-resources/publications/comptrollers-handbook/files/floor-plan-lending/pub-ch-floor-plan.pdf)). PACCAR's own financial disclosures confirm PACCAR Financial Services operates **dealer wholesale financing** — "floating-rate wholesale loans to PACCAR dealers for new and used trucks" — as a distinct, sizable segment of its Financial Services business ([PACCAR SEC 10-K filing](https://www.sec.gov/Archives/edgar/data/75362/000119312526057025/R32.htm); [PACCAR 10-K 2023](https://www.sec.gov/Archives/edgar/data/731288/000095017024017921/pcar-20231231.htm)), confirming the same lender-dealer floor plan relationship structure applies at Peterbilt/PACCAR truck dealers, with the GL liability side represented by accounts analogous to GM's `310/311 Notes Payable – New/Used Vehicles`.

## 7. Warranty receivable accounting

`DOCUMENTED`. Warranty claims create a GL receivable (GM `263 Warranty Claims`; Ford `1140 Warranty Claims Receivable`) that is debited when a claim is filed against the factory and credited only when the factory pays or rejects it — meaning the balance is inherently long-lived because payment timing is factory-controlled, not dealer-controlled ([GM manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf); [Digital Dealer](https://digitaldealer.com/news/your-dms-and-schedules/65829/)). Because claims can sit open for weeks to months and rejected claims must be tracked and either resubmitted or written off, the account requires **aged schedule reporting by RO/claim number** (30/60/90/120+ days), exactly the schedule mechanism in Section 2 ([Digital Dealer](https://digitaldealer.com/news/your-dms-and-schedules/65829/)). The GM manual explicitly notes that "Adjustment for the difference between the month-end schedule and the account balance" is itself a bookable entry — i.e., warranty receivable reconciliation breaks are a recurring, named accounting event, not an edge case ([GM manual](http://gm.acctmanual.com/misc/gm_acct_manual%20v2-2-1-1.pdf)).

## Proposed SAP-shape mapping

| CDK/dealer-accounting concept | Proposed SAP object/table | Rationale |
|---|---|---|
| GL account (3-digit + dept suffix) | `SKA1`/`SKB1` (GL account master, chart of accounts + company code segment) | Direct analog: natural account + controlling-area/cost-center-like department suffix |
| Department code (01–09) | Cost center or business area (`CSKS`/`TKA02`-style) | Departments are profit/cost segments, not separate legal entities |
| Schedule (controlled subledger, e.g., warranty, floor plan, factory receivable) | `BSEG`/`BSID`/`BSAD` (open-item subledger line items) filtered by a control field | Schedules are exactly SAP's open-item-managed subledger concept; the "control" field maps to SAP's account assignment/reference field |
| GL control account for a schedule | Reconciliation account (`SKB1-MITKZ`/recon account on customer or vendor master) | SAP already enforces "no direct posting to a reconciliation account" — matches "schedules controlled by GL, not directly postable" pattern described industry-wide |
| Journal type (Standard Entries, Cash Receipts, Payroll, etc.) | Document type (`BKPF-BLART`) | Each named DMS journal is a document-type-scoped posting source |
| Posting period / closed-period lock | Posting period variant (`OB52`/`T001B`) | Same architectural control the operator already knows from SAP FI |
| Trial balance | `S001`/GL account balance display (`FAGLB03`/`FBL3N` summary) | Direct equivalent |
| Factory/OEM formatted statement | Custom SAP drill-down report / FSV (Financial Statement Version, `FSE2`) mapped from the same chart of accounts | FSV is SAP's native mechanism for multiple statement presentations off one COA — matches the "Reporting Accounts per Financial Statement" pattern seen in Dominion DMS |
| Vehicle unit cost accumulation while in inventory | Material with order/project-based cost object (akin to `MSEG`/`AUFK` settlement) rather than plain `MBEW` moving average, because cost accrues discretely per VIN, not by weighted average | Each vehicle behaves like a make-to-stock cost-collector, not a fungible material |
| Floor plan payable / interest | Vendor/lender reconciliation account + periodic interest accrual document type | Standard AP-financing pattern; interest expensed, not capitalized, matching documented GM treatment |
| Warranty claims receivable | Customer (OEM) reconciliation account with open-item clearing by claim/RO reference (`BSID` cleared by assignment field) | Matches documented aged, RO-controlled receivable behavior |
| Fortellis `glpost`/`glwippost` APIs | Custom RFC/BAPI wrapper analogous to `BAPI_ACC_DOCUMENT_POST` | Both post a journal/document record into a live ledger from an external caller |
